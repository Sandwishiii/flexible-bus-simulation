## 1. 项目背景

**云公交（灵活公交）**——公交车像打车一样，有单子就去接送乘客。  
多辆公交车在路上运营，有订单时需要智能派单，选择更近或更顺路的车辆接单。

### 1.1 建设目标（来自需求文档）

1. 确定车辆数需求
2. 确定订单池请求合并策略
3. 确定算法参数，发现算法问题
4. 确定调度策略
5. 新区域初始参数确定
6. 提升测试效率

## 2. 核心算法

派单引擎基于 **网约车/出租车派单算法** 设计，核心为 **带权二分图匹配**：

| 策略 | 说明 | 实现状态 |
|------|------|----------|
| 延迟集中分单（Batch Matching） | 收集时间窗口内的订单和车辆，集中求解全局最优 | ✅ 已实现 |
| KM 算法（Kuhn-Munkres） | 求解带权二分图最优匹配，最小化全局接驾成本 | ✅ 已实现 |
| 贪心匹配 | 简单"就近派单"模式，作为对比基线 | ✅ 已实现 |
| 三层优先级派单 | P1:保障车内乘客 P2:缩短候车 P3:控制空载 | ✅ 已实现 |
| 方向夹角约束 | 车辆行进方向与订单上车点夹角过大时不接单 | ✅ 已实现 |
| 连环派单 | 即将完成当前任务的车辆优先接新单 | ✅ 评分中体现 |
| 供需预测 | 预测未来区域供需，提前调度 | ❌ 未实现 |

### 评分公式（三层优先级）

```
综合匹配分 = 0.50 × f(车内乘客保障 + 顺路程度)    # 第一优先级
           + 0.35 × f(接驾距离/候车时间)          # 第二优先级
           + 0.15 × f(空载控制)                    # 第三优先级
           × (1 - 负载均衡惩罚因子)
```

## 6. 技术方案要点（来自需求文档）

### 6.1 仿真引擎
- **类型**: 以进程为基础的离散事件仿真（PEDS）
- **框架**: 自主设计开发（不使用 SimPy/MATSim 等重框架）
- **并行**: 支持城市+区域+时间窗口并行计算

### 6.2 场景建模
- **地理信息**: 高德路网 + Redis 缓存站点轨迹导航数据（`flexible:stopTraceMap`）+ 主数据表 `s_ods_mdm_geo_stop_day`
- **出行需求**: 历史订单（`f_ods_flexible_match_order_history_day`）或预测生成
- **交通流**: 暂不考虑拥堵，假设固定速度行驶 ✅ 已按此实现

### 6.3 行为模拟
- **车辆模型**: 根据初始位置、订单指派、导航轨迹、行驶速度更新状态 ✅ 部分实现
- **乘客模型**: 暂不考虑 ❌
- **订单匹配**: 调用灵活公交算法服务 API ❌ 当前为内置算法

### 6.4 数据分析与可视化
- **技术方案**: POST 接口服务 + Streamlit 可视化 ❌ 待开发
- **指标计算**: 部分指标调用产品已有看板服务接口 ❌ 待对接

## 8. 关键设计决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 仿真框架 | 自研 PEDS | 需求明确不使用 SimPy 等重框架 |
| 匹配算法 | KM (scipy) | 滴滴验证过的全局最优方案 |
| 距离计算 | Haversine + 导航距离可选 | 支持直线距离和高德导航两种模式 |
| 导航缓存 | 本地 JSON 文件（NavCache） | 先跑通逻辑，后续平滑迁移 Redis |
| API限流 | 随机 0.3~2s + 指数退避 | 避免触发高德频率限制 |
| 车辆速度 | 固定 30km/h | 需求明确暂不考虑交通流 |
| 订单生成 | 泊松过程 | 经典排队论假设，可替换为历史回放 |
| 评分权重 | 距离0.4+顺路0.25+状态0.2+供需0.15 | 参照滴滴调研数据 |
| 非方阵填充 | 大值 1e6 | `-inf` 取负后变 `inf` 导致 scipy 报错 |
| OD→站点映射 | 最近站点 | O点→最近上车站，D点→最近下车站 |
| 仿真时段 | 高峰时段决定 | 高峰起始/结束 = 仿真起始/结束 |
| 车辆移动 | 按速度逐步移动+轨迹插值 | 派单时记录移动段，轨迹记录时线性插值 |
| 矩阵安全限制 | >50万元素降级贪心 | 防止内存爆炸 |

```
OD概率订单生成器(P0#1) → 车辆位置更新(P0#2) → ALNS全局优化(P0#5)
```

- 所有距离单位：米（m）；时间单位：秒（s）；速度单位：km/h
- 经纬度精度：保留 6 位小数
